# 主升初期识别算法设计

## 1. 先说清楚:95% 准确率和 30% 收益意味着什么

**"准确率"的定义**(报告、模型文件、APP 中统一使用):

> 信号日收盘发出 → 次日开盘价买入 → 之后 40 个交易日内,**先**涨到 +30%,而不是先跌到 −8%,算"命中"。
> 准确率 = 命中信号数 / 信号总数。同一只股票 20 个交易日内只算第一次信号(同一波启动不重复计数)。

这个口径直接对应你的要求:"一次周期盈利至少 30%",同时带了止损约束,不会把"先跌 20% 再涨 30%"也算成功。

**需要提前知道的事实:**

- 在 A 股真实数据上,满足候选条件的"启动日"里,事后真正走出"先涨 30%"的通常只占个位数百分比(训练时日志会打印这个"基准命中率")。模型要把它提升到 95%,只能把阈值提得非常高,信号会变得很少。
- 信号太少时,95% 没有统计意义:10 个信号中 10 个命中,真实准确率的 95% 置信下限只有约 72%。所以程序同时要求 **测试期信号数 ≥ `target.minTestSignals`**,并在报告里给出 Wilson 置信下限。
- 程序**不会**为了凑出 95% 而在测试集上调参。阈值、早停轮数、卖出参数都只在验证期选;测试期是从未参与任何选择的一段时间,只用来检验。达不到就如实标记"未达标"(文件名带 `-NOT-PASSED`,模型 JSON 中 `passed=false`),APP 应醒目提示。
- 如果真实数据达不到 95%,可以调整的杠杆(都是"信号数量"与"准确率"的取舍):
  - 收紧候选条件(`gate.*`,如提高量比、成交额);
  - 放宽成功定义(`label.target` 降到 0.2,或 `label.horizon` 拉长到 60);
  - 放宽止损定义(`label.stop` 到 0.10);
  - 接入更有信息量的数据(真实大单净量、流通股本、板块强度,见第 4 节)。
  每次调整后重新训练,看测试期指标;不要反复盯着同一段测试期调参,否则测试期也会被"间接拟合"。建议留最近半年数据做最终验收。

## 2. 整体流程

```
通达信离线日K ─┬─ .day(不复权,启发式除权)
               └─ 导出 txt(前复权,GBK 自动识别)
        │
        ▼
候选"启动日"筛选(硬条件,规则)  ──→ 每天全市场 5000 只 → 几十~几百只
        │
        ▼
70 个特征(K线组合 / 趋势位置 / 形态 / 量能 / 换手 / 资金 / 市场 / 板块)
        │
        ▼
标签:先涨 30% 还是先跌 8%(三重壁垒法)
        │
        ▼
时间切分:训练 | 验证 | 测试(按时间,不打乱;训练样本标签窗口不得伸入验证期)
        │
        ▼
GBDT 梯度提升树(验证集早停)
        │
        ▼
验证期:选阈值(去重后准确率 ≥ 95% 的最多信号)、网格搜索卖出参数
        │
        ▼
测试期:逐只股票流式回测(T+1、一字板、跳空、手续费)→ 达标判定
        │
        ▼
导出 model-*.json + report.md + 信号明细 CSV → APP 导入
```

### 2.1 为什么先用规则筛"启动日"

主升浪的第一根 K 线几乎都伴随价或量的异动。先用规则把样本限定在"有启动迹象"的交易日:

| 条件 | 默认值 | 作用 |
|---|---|---|
| 上市满 | 120 个交易日 | 剔除次新股阶段 |
| 5 日均成交额 ≥ | 3000 万 | 剔除流动性差、易被操纵的标的 |
| 当日涨幅 ≥ 3% 或 量比 ≥ 1.8(且收涨) | | 有启动动作 |
| 启动前 20 日涨幅 ≤ | 25% | 只要"初期",已经涨多的不要 |
| 当日收阳 / 剔除 ST / 复牌 5 日内不发信号 | | 过滤噪声 |

好处:① 模型专注于回答"这个启动会不会走成主升";② 样本量降一个数量级,内存可控;③ 这些条件就是 APP"硬条件"卡片上展示的内容,用户看得懂。

### 2.2 三类主升启动

每个信号会被标注类型(用于分类统计和 APP 展示,不作为硬过滤):

| 类型 | 判定 |
|---|---|
| 箱体突破 | 前 60 日振幅 ≤ 35% 且收盘突破前 60 日最高价,或前 30 日振幅 ≤ 20% 且突破 |
| 超跌反弹 | 距 250 日高点回撤 ≥ 30%,且 60 日跌幅 ≥ 10% 或近 10 日 RSI6 曾 ≤ 20 |
| 趋势波段 | MA60 向上、价在 MA60 上方、均线多头排列度 ≥ 2 |

三类共用一个模型(GBDT 会自动按特征分区学习各自规律);报告里分类型给出准确率,如某一类明显偏弱,可以在 APP 中只启用表现好的类型。

## 3. 特征(70 个)

全部是**比例/相对值**,不依赖股价高低;只使用信号日及之前的数据(单元测试 `featuresHaveExpectedShapeAndNoFutureLeak` 专门校验"截断未来数据后特征不变")。

### K线组合(16)
当日/3/5/10/20/60 日涨幅;实体占振幅比(阳正阴负);上、下影线占比;开盘跳空;连涨天数;当日涨停;近 10/60 日涨停数(**涨停基因**);阳包阴/反包形态;近 5 日大阳线数。

### 趋势位置(12)
60/250 日区间位置;距 250 日高点回撤;距 250 日低点涨幅;偏离 MA5/20/60/120;MA20、MA60 斜率;均线多头排列度(0–4);**均线粘合度**(MA5/10/20/60 的离散程度,"四线粘合"后发散是经典启动形态)。

### 形态指标(17)
30/60 日**箱体振幅**与**突破幅度**;布林 %b、带宽、带宽 10 日变化(**布林收口后开口**);MACD DIF、柱、柱斜率、金叉后天数;KDJ-J;RSI6、RSI14、近 10 日 RSI6 最低值(超跌痕迹);ATR、20 日波动率。

### 量能(9)
量比(对前 5/20 日);5 日/60 日均量比;**启动前 10 日缩量程度**(主力吸筹完毕的"地量");成交额(对数);20 日涨跌量比;20 日量价相关系数;OBV 20 日斜率;当日量 / 前 60 日最大量(天量)。

### 换手率(3)
换手率、5 日平均换手率(需要流通股本数据);**相对换手**(量 / 250 日均量,无需股本数据,总是可用)。

### 资金 / 大单(5)
- **估算主力净额**(当日、5 日、20 日):CLV 资金流 = 成交额 × [(收−低) − (高−收)] / (高−低),收盘越靠近最高价,买方越主动。这是没有 Level-2 数据时的替代。
- **大单净量**(当日、5 日累计):需外部数据(见下)。

> **重要**:通达信离线日线(.day)只有开高低收量额,**不包含大单/逐笔数据**。"大单净量"是 Level-2 指标,必须另行提供 `data.bigOrderCsv`(格式:`代码,日期,大单净量%`)。没有时这两个特征为空,模型自动只用估算资金流。

### 市场环境(5)
大盘(默认上证指数)5/20 日涨幅、大盘偏离 MA20;个股相对大盘 20/60 日强度(**RS 相对强度**)。弱市里个股启动的成功率明显更低,这组特征让模型学到"看大盘"。

### 板块属性(3)
板块(主板/创业板/科创板/北交所)、涨跌停幅度、上市天数(对数,封顶 750 日)。

## 4. 你可以继续加的指标(本版未实现)

| 指标 | 价值 | 数据来源 |
|---|---|---|
| 行业/概念板块强度 | 主升往往是板块共振,龙头先启动 | 通达信 `T0002/hq_cache/tdxhy.cfg`、`block_*.dat` |
| 市场情绪(涨停家数、连板高度、炸板率) | 情绪周期决定接力成功率 | 全市场日K二次计算 |
| 筹码分布(获利盘比例) | 套牢盘少的突破更容易走远 | 需逐日成交量分布,可用日K近似 |
| 北向/融资余额变化 | 增量资金 | 外部数据 |
| 财务(业绩预告、ROE) | 过滤"雷股" | 外部数据 / APP 的公告模块 |

新增特征的步骤:在 `FeatureDefs.ALL` 末尾追加定义 → 在 `FeatureEngine.compute` 中计算 → **把 `FeatureDefs.VERSION` 加 1** → 重新训练。APP 加载旧版本模型时会提示不兼容,避免口径错乱。

## 5. 模型:GBDT 梯度提升树

选择理由:表格型特征上效果最好的一类模型;能自动处理缺失值、非线性和特征交互;推理只是若干次比较,在手机上全市场扫描毫秒级;可解释(每个信号能给出"哪些特征加分/减分")。

实现要点(`trainer/GbdtTrainer.kt`,纯 Kotlin,无第三方依赖):
- 直方图算法:每个特征按分位数切成 ≤64 箱,样本以 1 字节/特征存储;
- 叶子优先生长(最多 31 叶、深度 6),最小叶子样本 200,L2 正则;
- 每轮 80% 行采样、80% 列采样;
- 验证集 logloss 连续 50 轮不降即早停;
- 缺失值单独成箱,每次分裂自动学习缺失值走左还是走右;
- 导出的阈值就是分箱边界的 float 值,APP 端推理与训练端**逐位一致**(单元测试 `binnedPredictionMatchesExportedModel` 校验)。

## 6. 卖出规则与动态止盈

```
止损:   最低价触及 买入价×(1−止损) → 卖出(跳空低开则按开盘价)
动态止盈:最高浮盈 ≥ 激活线后,最低价触及 最高价×(1−回撤) → 卖出
固定止盈:可选,最高价触及 买入价×(1+止盈) → 卖出
到期:   持有满 N 日按收盘价卖出
```
- T+1:买入当天不能卖;一字跌停卖不出,顺延;一字涨停买不进,信号作废。
- 同一根 K 线既触及止损又触及止盈时,保守地按止损处理。
- 动态止盈使用"截至前一日的最高价",避免回测中"先看到当天高点"的未来函数。
- `exit.gridSearch=true` 时在验证期从约 40 组参数(止损 6/8/10%,激活 10/15/20/30%,回撤 8/10/15%,以及固定止盈 30%)中选扣费后平均收益最高的一组,测试期只检验。

## 7. 检验(历史回测)

- **时间切分**:训练 | 验证 | 测试。训练样本的标签窗口必须在训练期内结束(purge),否则验证期的价格会通过标签"泄漏"进训练集。
- **去重**:同一只股票 20 个交易日内只取第一次信号;选阈值时也按这个口径(同一波启动连续多天满足条件,不去重会高估准确率)。
- **流式回测**:逐只股票读取、计算、释放,不把全市场数据放进内存。
- **组合模拟**:资金分 5 份,按信号先后与概率高低占仓,平仓后复利;按收盘价逐日盯市计算最大回撤(含持仓浮亏)。
- **成本**:默认单笔往返 0.3%(佣金 + 印花税 + 滑点)。
- **报告**(`report.md`):基准命中率、AUC、验证期/测试期准确率与收益、按年份、按启动类型、卖出原因分布、组合年化与回撤、评分因子权重。

## 8. 内存与异常处理

| 场景 | 处理 |
|---|---|
| 全市场数据量大 | 只为候选启动日建样本;样本按"每特征 1 字节"列式存储(800 万样本约 560MB);回测流式进行 |
| 内存接近上限 | 每处理 50 只股票检查一次:超过 `memory.maxUsage` 自动把训练期负样本保留比例减半;再超 8% 则停止追加并告警(股票顺序已随机打乱,截断不偏向某个板块) |
| 真的 OOM | 捕获 `OutOfMemoryError`,提示调大堆内存或调小 `sample.maxRows`/`gbdt.maxBins`/`threads`,退出码 3 |
| 堆大小 | `realu.bat` 默认 `-XX:MaxRAMPercentage=65`(物理内存 65%),可 `set REALU_HEAP=-Xmx8g` 覆盖 |
| 文件损坏/截断 | 长度非 32 倍数、日期非法、乱序、价格为 0、高<低 的记录逐条跳过并记录到 `data_warnings.txt` |
| 通达信正在写文件 | 读取失败的文件跳过,不中断训练 |
| 停牌 | 相邻 K 线间隔 > 20 个自然日视为长期停牌,复牌后 5 日不发信号 |
| 除权 | .day 模式按"开盘缺口超过跌停幅度"识别除权并前复权;精确复权请用前复权 txt |
| 新股 | 上市 120 日内不发信号;长周期指标预热期为缺失值 |

### 中文乱码(GBK/UTF-8)

乱码的根源都是"写入的编码"和"读取方假定的编码"不一致。逐一处理:

| 位置 | 问题 | 处理 |
|---|---|---|
| 控制台 | 中文 Windows 控制台默认代码页 936(GBK) | `realu.bat` 执行 `chcp 65001` 并以 UTF-8 输出;直接 `java -jar` 运行时自动探测控制台编码,探测到的编码无法表示中文时回退 UTF-8;可用 `console.encoding=GBK` 强制 |
| .bat 脚本 | cmd 按控制台代码页解析 .bat,内含中文易出错 | 脚本全部使用 ASCII |
| 通达信导出 txt | GBK 编码 | 先严格按 UTF-8 解码,失败自动按 GBK |
| 配置文件 | 记事本可能存为 ANSI(GBK) | 同上自动识别;Windows 反斜杠路径自动转换 |
| CSV 输出 | Excel 打开无 BOM 的 UTF-8 会乱码 | 默认写 UTF-8 + BOM;可配置为 GBK |
| 日志 / 报告 / 模型 | | 始终 UTF-8 |
| 输出文件名 | 系统编码不一致时中文文件名会乱码 | 文件名只用 ASCII |
